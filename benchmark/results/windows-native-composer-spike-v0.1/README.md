## F01 acceptance/wake proof (this candidate)

- **Old model:** `pending_wake=true` conflated an in-flight callback with confirmed signalling; lifecycle signalling was outside the acceptance mutex.
- **Single state authority:** `MailboxState` owns the callback, failure latch, and `Uninstalled { owed } | Idle | Confirmed | Terminal` state. Lifecycle pokes, producer acceptance, installation, `wake_seen`, and closure serialize under one mutex. Only callback success publishes `Confirmed`; only `Confirmed` permits installed-edge coalescing.
- **Installed acceptance:** insertion plus successful signalling or reuse of a confirmed edge, under that mutex. Direct triggering failure rolls back the exact envelope and returns `Wake`; producers overlapping a failed lifecycle signal serialize behind closure and return `Closed`.
- **Pre-install contract (Option B):** successful sends record startup obligations, not confirmed signals. `install_wake` synchronously resolves owed work and returns `Err(Wake)` on failure; Windows initialization maps the failure to a typed platform error through owned `bail` teardown. Pre-install sends are not claimed to have an already-signalled kernel event.
- **Wake observation:** `wake_seen` consumes only `Confirmed`; it never clears pre-install obligations. Work arriving before observation is covered by the current turn; work arriving after observation establishes a fresh signal.
- **Locking:** the bounded production signal callback reads the atomic window-close flag and calls `SetEvent`; it must not re-enter Mailbox. Detached callback destruction, envelope/Charge drops, and waiter wakes occur after unlock. There is no state/wake lock-order pair, spin loop, retry thread, or polling timer.

| Case | Claim | Proof |
|---|---|---|
| A/B | Direct sync/async failure -> triggering `Wake` | `mailbox_wake_failure_rejects_the_triggering_send`, `mailbox_wake_failure_rejects_the_triggering_async_send` |
| C/D | Lifecycle in-flight failure -> overlapping sync/async `Closed`, exact payload drop | `lifecycle_inflight_failure_serializes_overlap_send_closed`, `lifecycle_inflight_failure_serializes_overlap_async_send` |
| E | Lifecycle in-flight success -> sync/async `Ok`, callback count 1, exact payload / no duplicate | `lifecycle_inflight_success_serializes_then_overlap_send_ok`, `lifecycle_inflight_success_serializes_then_overlap_async_send_ok` |
| F | Pre-install obligation; install failure explicit error | `preinstall_owed_then_failing_install_reports_wake`, `lifecycle_owed_survives_wake_seen_until_install` |
| G | Confirmed coalescing, FIFO, callback count | `confirmed_edge_coalesces_across_pushes`, `mailbox_event_coalescing_delivers_everything_once` (native Backend, counting seam) |
| H | Consumed-before-`wake_seen` and fresh-edge interleaving | `wake_seen_edge_interleaving_uses_real_event` |
| I | Terminal waiters/task non-stranding, post-close producers | `mailbox_wake_failure_wakes_registered_waiters`, `mailbox_wake_failure_rejects_the_triggering_send` post-close assertions |
| J | Native idle blocking, no production polling | `mailbox_wait_blocks_when_idle` (bounded 512-post busy-queue native test `mailbox_event_wakes_through_busy_message_queue` is busy posted-message load, NOT quota-exhaustion proof) |

**Authority summary:** one `MailboxState` acceptance/wake authority, one `MailboxEvent::signal` `SetEvent`, one run wait, one `terminal_locked`. `WM_PUMP` is a separate same-thread reentrant continuation, not the cross-thread wake authority.

## What is proven (measured)

- Retained + keyed staged UI tree; windowless RichEdit via `ITextHost2`/`ITextServices2`/`TxDrawD2D`
- **Coordinate contract:** `crate::geom` owns semantic spaces (`ScaleFactor` = platform-neutral px/Dp ratio, `PeerOrigin` single snapped transform, `ClientPhysicalPoint`/`ScreenPhysicalPoint`/`PeerLocalPoint` markers); `platform/win32/space.rs` owns all Win32 conversions (RECT/POINT/LPARAM packing, checked `ClientToScreen`/`ScreenToClient`, the `dpi ↔ ratio` mapping)
- **Native entry:** all WndProc→Backend entries pass one ownership guard; reentrant callbacks enqueue OWNED payloads (`WM_DPICHANGED` copies the RECT; `WM_NCDESTROY` atomically closes + queues full cleanup through the drain); the drain re-evaluates the COMPLETE queue after every pass so teardown produced MID-dispatch still runs in the same drain; deferred peer delivery is generation-checked with explicit continuation; the mailbox wake is ONE Arc-owned auto-reset event — every signal goes through the same checked `SetEvent` path, invoked under the ONE `MailboxState` mutex that serializes lifecycle pokes, acceptance, `install_wake`, `wake_seen`, and close (only callback success publishes `Confirmed`; only `Confirmed` coalesces; a pre-install send records an `Uninstalled { owed }` startup obligation that `install_wake` discharges synchronously, returning typed `Err(Wake)` on failure), and `MsgWaitForMultipleObjectsEx` waits on event+queue together — the triggering send's own signal failure rolls its envelope back and returns typed `Wake`, a producer overlapping a failed lifecycle signal serializes behind the terminal close and returns `Closed`; wait results are fully classified (`WAIT_FAILED`/undocumented -> typed terminal) — queue capacity and drain budget are separate authorities (`REENTRANT_QUEUE_CAP` > `REENTRANT_DRAIN_MAX`)

## Honest limits

- **Real monitor DPI transition** — NOT RUN; the display stayed at 125%. Synthetic `WM_DPICHANGED` + adapter-unit coverage is recorded; a real monitor/scale move remains a distinct acceptance class.
- **Dead keys** — NOT RUN; en-US has none and no international layout is installed.
- **IME composition across scale relatch** — the relatch is composition-safe (deferred while a composition is active, drained at composition end); a COMBINED real-IME + real-DPI-transition run is not claimed.
- `ElementProviderFromPoint` — unit-tested; real `FromPoint` against the foreground window not exercised.
- Caret visibility in `PrintWindow` captures is unreliable (XOR caret); caret geometry validated via click→insert.
- **PrintWindow is not text-fidelity evidence** — it re-renders the window into an offscreen DC and can clip windowless-RichEdit glyphs; text/layout fidelity claims use UIA rects and the physical-display `Shot-Screen` capture. `details-pw.png` vs `details-screen.png` are kept side by side deliberately.
- **IME mode is profile-persistent** — engagement is therefore VERIFY-DON'T-TOGGLE: target-thread layout activation, IME open state, and the exact conversion-mode bits are all read back and asserted; when verification is unavailable the scenario fails with a typed prerequisite error rather than toggling unknown persisted state.
- `requested_redraws`/`caret_redraws` counters are demand-driven repaint counts, not a resource-leak audit; no leak-freedom claim is made.
